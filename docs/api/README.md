# ChurnCast backend API contract

This folder documents the REST contract a future backend must implement so it can be connected
to the existing dashboard with **zero frontend code changes** — see
[openapi.yaml](./openapi.yaml) for the full machine-readable spec (OpenAPI 3.0; viewable at
[editor.swagger.io](https://editor.swagger.io) or generatable into Spring Boot controller stubs
via `openapi-generator`).

There is **no backend yet**. The dashboard currently reads the static JSON files in
[frontend/public/data/](../../frontend/public/data) and simulates the two prediction actions
client-side. The frontend infrastructure for connecting a real backend is already built and
wired into every chart that should show live predictions:

| Frontend piece | What it does |
|---|---|
| [apiConfig.js](../../frontend/src/data/apiConfig.js) | Single on/off switch: reads `VITE_API_BASE_URL`. Unset = static JSON mode (today). Set = live API mode. |
| [apiClient.js](../../frontend/src/data/apiClient.js) | Typed `fetch` wrapper for every route below (`predictChurn`, `predictRevenueForecast`, `triggerModelRetrain`). |
| [useDataset.js](../../frontend/src/data/useDataset.js) | Every `GET` dataset hook (customers, monthly revenue, calibration, drift, …) automatically fetches from the live route instead of the static JSON once connected — this is what makes ChurnDonut, ForecastChart, CalibrationChart, DriftSmallMultiples, etc. show WEKA's real output with no extra wiring. |
| [usePrediction.js](../../frontend/src/data/usePrediction.js) | Drives the Customer Risk Explorer "What-If" panel: calls `POST /predictions/churn` live, falls back to the existing client-side formula if no backend / on error. |
| [useRevenueForecast.js](../../frontend/src/data/useRevenueForecast.js) | Drives the Overview page's "Refresh WEKA forecast" button: calls `POST /predictions/revenue-forecast` and merges the result into the exact rows `ForecastChart` renders. |

## Connecting a real backend

1. Implement the routes in [openapi.yaml](./openapi.yaml) (Java + Spring Boot + WEKA is the
   intended stack — WEKA for the churn classifier and revenue regressor, Spring `@RestController`s
   returning the JSON shapes defined there).
2. Enable CORS for the dashboard's origin (`http://localhost:5173` in dev).
3. In `frontend/`, copy `.env.example` to `.env` and set:
   ```
   VITE_API_BASE_URL=http://localhost:8080
   ```
4. Restart `npm run dev`. Every page now reads live data and live predictions — no other change
   needed.

## Why the shapes match the static JSON exactly

Every `GET` schema in `openapi.yaml` mirrors a file already in `frontend/public/data/*.json`
(generated by `data/generate_sample_data.py`). That means:

- The static JSON files double as **sample/mock responses** for backend development and testing.
- A backend can be built and validated table-by-table against files that already exist in this
  repo, without guessing field names or types.

## Predictive endpoints (the "WEKA AI" part)

Two `POST` endpoints are new (not just a reflection of a static file), because they represent
*on-demand* model inference rather than a precomputed table:

- `POST /predictions/churn` — churn prediction for the Customer Risk Explorer's what-if slider.
- `POST /predictions/revenue-forecast` — next-month (or N-month) sales/revenue forecast for the
  Overview page's forecast chart.
- `POST /model/retrain` — triggers retraining of both WEKA models; after it completes, re-fetching
  `/model/meta`, `/model/backtest-metrics`, `/model/calibration`, `/model/drift-metrics` should
  reflect the newly retrained model (the Model Diagnostics page already refetches these
  automatically after a successful retrain call).
